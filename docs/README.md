# s-m-r-t documentation site

The Docusaurus site combines authored guides in [`content`](./content/) with every workspace package README, including nested workspaces.

## Development

```bash
pnpm --dir docs install
pnpm --dir docs dev
```

`predev` and `prebuild` run `scripts/copy-readmes.js`. The script discovers packages from `pnpm-workspace.yaml` and copies their READMEs into the generated `content/packages/` directory; there is no hand-maintained package allowlist. Repository-local links are rewritten to canonical GitHub source URLs so they remain valid after the README moves. The sidebar autogenerates package navigation from that directory.

## API reference

There is no generated API reference. The site's API surface is each package's
own README (copied into `content/packages/` as described above) plus the
package `AGENTS.md` files, which the knowledge tooling
(`pnpm smrt dev:knowledge-check`) keeps honest against the source.

The site used to publish a TypeDoc tree at `content/api/`. It was retired in
#2270: it covered 12 of 63 packages, and one package's output (`accounts`) was
generated from source that had since been renamed to `ledgers`. The
hand-maintained sidebar did link to it, but #2068 replaced that sidebar with the
autogenerated one, which does not — after which the only inbound links were
eight of our own guide pages, and nothing outside this site consumed it at all.
Do not reintroduce generated API output without a consumer and a CI freshness
gate; that combination is what let the old tree drift unnoticed.

Validate the repository README system before building the site:

```bash
pnpm check:readmes
pnpm docs:site:build
```
