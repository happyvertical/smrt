# Ingestion behavior-to-test contract

Design for [ADR 0004](../adr/0004-application-aware-ingestion.md), #3669. **All runtime rows below are planned, not executed.** #3669 adds documentation only; it cannot establish database, provider, browser or accuracy guarantees. Each child must replace planned evidence with full command output tied to its reviewed commit before shipping. High risk: authority, tenant/confidential isolation and concurrent durable mutation.

## Frozen future commands

#3670 creates these scripts in `@happyvertical/smrt-ingestion`; they do not exist at this contract revision. Each command runs its full lane, without silently skipping unavailable prerequisites:

| ID | Exact command | Required lane |
| --- | --- | --- |
| U | `pnpm --filter @happyvertical/smrt-ingestion test` | Full Vitest suite, real SQLite, `smrtVitestPlugin()` |
| P | `pnpm --filter @happyvertical/smrt-ingestion test:postgres` | Real PostgreSQL, including negative authorization and concurrent transactions |
| X | `pnpm --filter @happyvertical/smrt-ingestion test:providers` | Maintained PDF/OCR/image/speech integration fixtures; explicit configured provider prerequisites, missing prerequisites fail |

| T | `pnpm --filter @happyvertical/smrt-ingestion typecheck` | TypeScript plus svelte-check once /svelte exists |
| K | `pnpm --filter @happyvertical/smrt-ingestion build` | Build, manifest and server/browser boundary smoke tests |
| E | `pnpm --filter @happyvertical/smrt-ingestion test:evaluation` | Frozen held-out corpus and per-action thresholds, no threshold fitting |

U/P use repository Node (>=26); browser runs use maintained Chromium. Only SQLite and PostgreSQL are supported ingestion v1 dialects; DuckDB/JSON/edge must fail capability checks. Commands with multiple IDs mean **each** exact command runs. Fixtures and scratch state live in a short writable directory outside `/tmp` per TESTING_STANDARD; full stdout/stderr and exit codes live outside the worktree. Changes to existing owner packages add their complete documented suites, including maintained browser suites, to the gate. Run package suites first, then relevant root test/typecheck/lint/format-check/knowledge/audit checks. SDK fixes, if needed, require owner-repository evidence.
