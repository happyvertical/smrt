# Protected package publication test matrix

Issue: [#27](https://github.com/happyvertical/smrt-planner/issues/27)

| Behavior / invariant | Reachable trigger | Positive case | Negative / failure case | Actor / context | Data executor / transaction | Supported runtime / dialect | External contract edge | Test level | Validation command |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Only `main` may enter the release environment | A manual Publish package dispatch | A dispatch from `main` finds one exact `main` deployment branch policy | A non-main ref, missing environment, broad protected-branch policy, or additional branch policy fails before a secret-bearing job starts | Repository maintainer / GitHub Actions | N/A: workflow control plane, no application transaction | GitHub-hosted Ubuntu / Node 26 | GitHub Environments API missing or malformed response fails closed | Workflow contract inspection plus Actions run | `pnpm test:release-workflow` |
| Existing organization publish credentials are read only by protected publication jobs | A primary or mirror publish job starts | The job declares `environment: release` before reading `NPM_HAPPYVERTICAL_PUBLISH_TOKEN` or `NPM_TOKEN` | A publish-secret reference in a pull-request workflow or a job without the environment fails the contract check | GitHub Actions release job | N/A: registry mutation is performed by npm after authentication | npm CLI on GitHub-hosted Ubuntu | Missing secret, invalid token, or wrong registry aborts before publication; organization-wide visibility remains tracked in `happyvertical/iac#2165` | Workflow contract inspection; live proof belongs to the approved first release | `pnpm test:release-workflow` |
| One validated tarball supplies both registries | Release mode builds version `0.0.1` | Build, package, packed-consumer verification, artifact upload, downloaded-artifact `npm publish --dry-run`, primary publish, and npmjs mirror use the same artifact | An ambiguous tarball path, existing version with different integrity, or changed artifact aborts before publication | GitHub Actions release job | npm package-version write; immutable after success | Node 26 / pnpm 11.25 / npm registries | Registry 404 means unpublished; other lookup errors fail closed | Downloaded-artifact publish-input check, package consumer integration, and workflow contract inspection | `pnpm package && pnpm pack --pack-destination "$TMPDIR" && pnpm test:package -- "$TMPDIR"/*.tgz && npm publish --dry-run --ignore-scripts "$TMPDIR"/*.tgz && pnpm test:release-workflow` |
| A partial release can be retried without changing primary bytes | Primary succeeded and the npmjs mirror failed | `mirror` mode downloads the primary tarball, checks its integrity, then retries only npmjs | A missing primary version, integrity mismatch, or unavailable token fails the retry | Repository maintainer / GitHub Actions | npmjs package-version write; primary remains read-only | npm CLI on GitHub-hosted Ubuntu | Unknown registry failures are not treated as absence; npmjs propagation is rechecked | Workflow contract inspection; live proof belongs to a mirror retry if needed | `pnpm test:release-workflow` |
| Consumers receive the fixed Kitchen fragment-token dependency floor | A consumer installs the planner | Planner dependencies resolve SMRT `0.55.12` or later and the packed core/app imports run | The lockfile or manifest retaining `0.55.11` fails validation | Package consumer | N/A: package installation only | Node 26 / pnpm 11.25 | Private-registry dependency resolution failure is visible during install | Packed consumer integration | `pnpm install --frozen-lockfile && pnpm package && pnpm pack --pack-destination "$TMPDIR" && pnpm test:package -- "$TMPDIR"/*.tgz` |

The workflow and credential boundary are release/lifecycle and security
changes, so review risk is high. Live registry mutation is intentionally absent
from pre-merge evidence; the protected first Actions run supplies that final
evidence after the protected environment is configured.
