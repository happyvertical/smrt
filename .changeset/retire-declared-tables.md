Migrate can now retire a table. A package declares it in `smrt.retiredTables` in its `package.json`: the table (lower case), its last owning class, the release, a reason, `rows: 'discard'` when the rows may go, and a `definition` of the table's last declared columns and types, written from a published release's manifests by `scripts/retired-table-facts.mjs`. The declaration travels in the package manifest, the registry and the app's build, is checked wherever it enters, keeps its own package, and drops out of the app's merged manifest when the app no longer depends on the package. Its list is part of the build's schema stamp, and the plan and the stamp read the same set. A whole-schema `smrt db:migrate` drops a declared table, and only that. It stops by name when the entry fails its checks, when a model or a stored run-time list still declares the table, when the live table does not match the declaration's definition, when it holds rows without `rows: 'discard'` (counted again inside the batch, after a lock on PostgreSQL), when anything undeclared depends on it (foreign keys, views, triggers, functions, DuckDB macros, and on PostgreSQL anything `pg_depend` records), or on the JSON adapter. A run limited to named tables neither plans nor waits on a retirement; it stops only when it would create or add to a retired table. On PostgreSQL every statement names the `public` schema. `smrt doctor --db` lists each retirement with its reason, and the release upgrade gate checks each declaration against the release snapshots and their owners files. `ObjectRegistry.registerManifestRetiredTables()` and `DiffOptions.retireDeclaredTables` are the public entry points. Refs #5005.
